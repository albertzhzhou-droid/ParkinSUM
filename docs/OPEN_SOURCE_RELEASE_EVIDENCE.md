# Open-source release evidence

`tool/open_source_release_evidence.mjs` verifies Flutter's generated license
notice in built release outputs and writes a JSON evidence sidecar plus a
CycloneDX 1.7 document for each requested artifact. The default mode requires
both `build/web` and
`build/app/outputs/flutter-apk/app-debug.apk`; Web-only production preflights
may pass `--web-only`.

The verifier checks that Web contains a non-empty `assets/NOTICES`, Android
contains a readable gzip `assets/flutter_assets/NOTICES.Z`, and the decompressed
Android bytes exactly equal the Web notice bytes. It records a digest of every
Web output file and the complete APK, along with SHA-256 values for `pubspec.lock`,
`package-lock.json`, the open-source influence inventory, and the schema catalog.
When present, Android's `META-INF/NOTICE.md` is recorded separately.

Schema v3 reconstructs the NOTICE bundle with the source-selected behavior from
the Flutter version pinned in CI. It requires the local Flutter SDK HEAD to match
the inventory's full source revision and compares the relevant
`license_collector.dart`, `asset.dart`, and `flutter_manifest.dart` files to that
commit. It reads the resolved roots in `.dart_tool/package_config.json`, selects
`NOTICES` before `LICENSE`, reproduces Flutter's 80-hyphen splitting, package
name grouping, duplicate-text merging and sort order, then appends manifest-
declared extra license files in the order produced by Flutter's dependency
traversal. Top-level notice/license inputs are collected from all package-config
entries; extra license files follow the app/runtime versus dev-only selection
used by Flutter's asset builder. The Web NOTICE must match the reconstructed
bytes exactly or evidence generation fails closed. The Android bundle must
also match the Web bundle byte for byte. The root Pubspec may declare additional
license files; the checked-in Geist, Geist Mono, and Source Serif 4 OFL texts
are now declared there and must appear in rebuilt platform NOTICE bytes. This
checks notice inclusion only. It does not resolve the Source Serif Reserved
Font Name condition for generated static font files or complete external legal
review.


This reconstruction checks the local generated bytes against the selected local
inputs and pinned collector sources. It does not verify extracted Pub cache
files against the hosted archive hashes in `pubspec.lock`, infer SPDX license
identifiers, establish complete legal obligations, or constitute legal approval.
The previous schema-v2 normalized-whitespace whole-document text-presence count
is superseded and is not package-attribution or coverage evidence. All
CycloneDX package license assertions remain `NOASSERTION`.

The Pub BOM includes the dependency graph reachable from the root package's
`dependencies`; dev-only components remain outside the release BOM. The
Android BOM also includes the resolved `:app` `debugRuntimeClasspath` graph.
Maven modules retain their group/name/version coordinates and resolved artifact
file hashes. Flutter plugin Gradle projects map back to package names in
`.flutter-plugins-dependencies`; each mapped name must exist in the Pub package
graph and lock. Those local projects are bound to their Pub archive hash rather
than separately hashing the generated Gradle project output. The report hashes
both the exported Gradle graph and Flutter plugin metadata. The Android
`META-INF/NOTICE.md` is also recorded as one platform notice entry. Schema v2
of the Android graph exporter records every matching license/notice member
inside each resolved Maven JAR/AAR/ZIP by archive path, byte length, and SHA-256;
the Android BOM binds these records to the resolved artifact filename and
archive digest. A first local scan of direct archive members matched all 143
resolved archive hashes and found 10 license/notice files in 9 archives; that
count does not include documents inside nested JARs. The schema-v2 exporter
also scans nested JAR/ZIP members to a bounded depth of two. A synthetic
Gradle regression applies the production init script to an AAR containing a
direct NOTICE, a nested JAR LICENSE, and a depth-two ZIP COPYING file, then
verifies all three member paths, byte lengths, and SHA-256 values. Modules
without published artifacts and archives without matching documents remain
uncovered. These records do not adjudicate every module's legal terms or prove
full notice completeness. The real application graph export has not completed
locally because the offline cache lacks a Kotlin Gradle plugin requested by
the resolved `share_plus` build; CI must validate that task before release
acceptance.

Reachable Git or path Pub packages, unresolved Gradle dependencies, unmapped
local projects, unsupported component identities, dangling edges, unreachable
graph nodes, and a collector-reconstruction mismatch fail closed. The
composition remains explicitly `incomplete`: dependency resolution does not
prove which components entered the APK. The Android graph omits Gradle
buildscript/plugin classpaths, Android SDK/NDK inputs, configurations other
than `debugRuntimeClasspath`, Node tooling, the development-only Google CQL
and FhirProto Go modules/toolchain, the CQF CQL JVM Gradle/Maven development
graph, and other release platforms.

CI exports the Android Gradle runtime graph after building the Web release and
Android debug APK, runs the evidence tests and two-platform artifact check,
then uploads the report, graph, and both BOM files. `tool/release_deploy.sh`
and `tool/firebase_production_acceptance.sh` also produce Web-only sidecars
after their production-configured Web builds. The sidecar has no timestamp so
equal inputs keep the BOM component and dependency content stable. Each
CycloneDX document receives a fresh serial UUID, so its exact file and the
report's statement ID differ between generations; a separate content digest
excludes that UUID. The report records the Git commit and whether the worktree
was clean. It validates the influence inventory's exact JSON schema-v7
URI/version and requires its declared Flutter-generated NOTICE mechanism; the
ParkinSUM schema catalog's local compatibility marker is versioned separately.

These documents are partial dependency inventories, not complete artifact
SBOMs. They do not establish license terms for every Maven module, prove
target-binary inclusion, attest a signed release, satisfy source-offer
obligations, or replace legal review. They establish release hygiene only and
do not imply scientific validity, clinical effectiveness, data-use permission,
or regulatory clearance. The open-source license firewall queue item therefore
remains open.

Run locally after matching builds and Flutter dependency resolution:

```sh
npm run open-source:release-evidence:test
npm run open-source:android-gradle-graph
npm run open-source:release-evidence
```

The graph export uses the existing Android Gradle wrapper and writes
`build/open_source_release_evidence/android_gradle_debug_runtime_graph.json`.
Its launcher selects an available JDK 17+ from `PARKINSUM_JAVA_HOME`,
`JAVA_HOME`, or the installed Android Studio JBR, then runs Gradle offline.

The default outputs are `build/open_source_release_evidence/latest.json`,
`latest.web.cdx.json`, and `latest.android.cdx.json`.
