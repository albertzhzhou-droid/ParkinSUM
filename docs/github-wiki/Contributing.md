# Contributing

Contributions are welcome when they improve clarity, safety, accessibility, deterministic behavior, or synthetic-data demonstrations without weakening the public boundary.

## Good Contribution Areas

| Area | Examples |
| --- | --- |
| Documentation | README clarity, Wiki pages, GitHub Pages copy, safety wording. |
| UI polish | Accessibility labels, responsive layout, synthetic demo surfaces. |
| Deterministic evidence | Rule explanation structure, provenance fields, replay artifacts. |
| Testing | Negative safety-copy tests, importer fixture tests, public preflight coverage. |
| Demo media | Synthetic screenshots and GIFs that pass the media checklist. |

## Contributor Safety Rules

- Do not submit personal health information.
- Do not submit real medication schedules.
- Do not submit credentials, service-account keys, tokens, or private Firebase exports.
- Do not add clinical claims, medical advice, or patient-care language.
- Keep public examples synthetic/demo-only.

## Suggested PR Checklist

```text
- [ ] Change uses synthetic/sample data only.
- [ ] No real health data, credentials, UIDs, or local paths are exposed.
- [ ] Public wording stays educational and non-clinical.
- [ ] Relevant tests or preflight checks were run.
- [ ] README/Wiki links still point to existing files.
```
