# Capability Matrix

Educational/research prototype. Model validation and public demonstrations use
synthetic/demo data; local record workflows can contain user-entered personal
health information. Not medical advice, not clinically calibrated, and carries
no clinical-validation claim.

This matrix summarizes what ParkinSUM Companion's local record workflows and
evidence/traceability layer actually implement, how they are exercised, and
where their boundaries are. Status values:

- **implemented** — runtime code, exercised by unit tests.
- **fixture-tested** — implemented and validated against synthetic fixtures only
  (no live ingestion).
- **deterministic-report** — a deterministic CLI/report artifact for review.
- **documentation-only** — described in docs; not a code capability.
- **future-work** — not implemented; recorded for transparency.

## Cross-cutting boundaries


All capabilities are **educational and non-prescriptive** and make **no FHIR
conformance** or clinical-validation claim. Validation fixtures and public
demonstrations use synthetic/demo data; the local care workspace, observations
and visit reports can contain personal health information and owner identifiers.
PHI-free boundaries apply only to the specific artifacts identified above.
The new care workspace is account-scoped on one device, excluded from current
portable-data backups, and provides no cloud caregiver sharing or authenticated
clinician workflow. Its new UI and report copy support Chinese and English,
with English fallback for other locales, rather than full application-wide
language coverage. The model is **not clinically calibrated**. Source-quality
and provenance signals affect modeled confidence and tie-breaking only and
never override conflict-overlap dominance, source-authority, or jurisdiction
policy. Personal observations and feedback do not infer treatment or change
the underlying rule evaluation.
