# 冲突算法研究与有界升级

核查日期：2026-09-29（America/Toronto）。本文件记录当前活动库的本地实现与原始资料核查；不是临床验证、发布记录或用药建议。原规划的“本轮只规划”是文档历史状态，本次实施授权来自用户的新请求。

## 1. 研究问题与证据边界

本轮问题是：同一营养/药品事实是否具有可比范围；缺失是否会被误当为零；口服吸收规则是否错误适用于其他途径；回放与证据状态历史是否可被独立检查。没有为既有机制模型引入新的临床系数，也没有将研究轨迹升级为决策权限。

## 2. 已实施的冲突边界

- 事实分类与聚类首先匹配 entity、属性、单位及 basis；品牌、盐型、植物部位、品种和实际 scope hash 参与可比性。不同范围的数值不再直接升格成同范围矛盾。缺失 scope 元数据不会因 `null == null` 被当作已证明同范围。
- 缺失、解析不确定、非有限或反向区间不能压过测得的零。不可用手工选择会被拒绝，不能生成伪造覆盖。重复/空观察 ID 以及异构聚类显式拒绝。
- 严格 `<10` 与精确 `10` 没有交集，`<=10` 与精确 `10` 有交集；测试使用独立手算预期，未用同一函数计算预期，也没有用 epsilon 掩盖端点差异。
- 蛋白和铁盐的两个基线规则要求明确 `oral` 路线。吸入、皮下、未指定、未知或空路线进入 `REQUIRE_REVIEW` 与明确的 withheld 说明。没有警示不代表已证明安全。
- 旧餐食评分中的蛋白、时序、高脂与铁盐 modifiers 也要求明确口服路线；未知或其他途径不再施加这些口服数值因素，同时保留规则的复核权重与 `REQUIRE_REVIEW`，不会改为 `ALLOW`。明确口服的正例仍保留这些既有工程因素。
- 餐食的 `missingNutrientFields`/目录缺失标记传入 runtime context。缺失蛋白序列化为 `protein_g: null` 并带显式标记，触发专门的复核门禁；测得 `0 g` 仍保留为零。合成规则测试包能保留该差异。
- 目录投影与实际餐食聚合复用同一 point selector：每项营养只有一个非负、有限 exact 主观测及一个来源文档身份时才可进入点值。重复 exact、竞争的 lt/gt/missing/普通 range、明确不符的单位或 basis 均 withheld，不能回落到缓存数字。只允许有 `:sample_range` locator、明确 source_min/source_max、与区间界限相符且包围点值的同源附属样本统计与 exact 共存；统计区间保留为证据，不作为点值。
- 明确 unit 必须与属性匹配；明确 basis 必须是 `per_100g` 或 `per_100g_edible_part`、basis amount 为 100。历史未携带这些字段的记录维持兼容，但不会凭空补出来源测量证明。缺失数值占位不再参与蛋白/时序评分或显示为确定总量；高脂/高热量阈值需要三项宏营养均已知。缺失信息采用原工程活跃窗的 8 小时上界，不借未知营养缩短该窗口；这不是临床保护间隔。
- 现有 10 g、60/120 分钟仍是未校准的工程默认值，动作元数据明确标记 `operational_default_unspecified_by_label`。现有即时释放机制模型的剂型/途径限制未放宽。

这些是范围、表示和失效处理的改进，不是生物学真实性排序，也不是冲突评分的临床校准。当前精确基线包 digest 更新为 `a42839ece070e0d2dd65d132a7fc0e66ce3cf3e93a9e45460b04402f6e5edfc4`；注册表源码身份与 schema pins 由统一生成过程重新绑定。

## 3. 回放异常包

`MechanisticReplayCapsule.fromJsonString` 是不可信原始 JSON 的入口，先检查 UTF-8 大小（含边界不超过 2 MiB）、容器深度（不超过 32）与重复成员，再解析和执行现有 schema/digest 验证。重复键检查识别转义后相同的键，并覆盖嵌套对象与数组中的对象。`fromJson(Map)` 保留为已结构化、可信输入的兼容入口；它不能追溯被其他解析器抹掉的重复成员。

异常语料覆盖重复根成员、转义后重复成员、数组内重复成员、超深、UTF-8 超大、未来 schema、损坏 digest 与截断 JSON。Dart 与独立 Node 入口比较接受/拒绝及原因类别。现有 schema 1 内容身份与规范化规则不改；工程传输限制是新增边界。3 个有效机制场景与 8 个异常包已通过 Dart/Node 对照；这不代表任意 JSON 的跨运行时全面等价。

本地 SQLite 单包行和浏览器存储数组的读取均经过原始文本检查。浏览器 archive 另有 16 MiB 上限、容器深度多允许外层数组的一层，每个单包仍受 2 MiB/32 层限制；写入前验证可回读。实际 SQLite 行和浏览器存储测试构造了“最后一个重复值与原值相同，因此旧解析会保留原 digest”的负例：现在拒绝读取与覆盖写入，原始历史文本保留。未改变 archive 的既有数组存储形式或单包 schema 版本。

## 4. 离线候选与历史回执

候选比较在同一明确 UTC 时刻，分别调用现有 evidence-currency gate，输出声明变更、provider disposition 和两侧完整历史快照。没有候选激活接口。来源修订、撤回、过期或覆盖缺失仍按原有门禁处理，不另建第二套规则引擎。

诊断页面的“本地证据来源检索”附带固定合成候选：仅将第一条登记声明设为撤回，并显式说明这不是发现真实撤回。页面显示记录状态与按检查时刻计算的有效状态，以免把已过期状态混作新变更；可展开已保存的基线与候选快照。

回执复用现有 SharedPreferences 后端，独立 owner-hash key、128 条容量及现有 JSON 字节限额。达到容量或遇到损坏/未来 archive schema 时拒绝新写入，保留既有数据，不自动淘汰历史。页面持有会话 epoch；账户 A→B→A 不会复活旧读取，pending save 会在持久化前再检查授权。owner key 隔离和租约测试已覆盖这些事件。回执哈希只能检查内部一致性，不证明外部来源或签发者真实性。

跨实例读取测试证明本地序列化回读；不是物理设备崩溃、断电或跨版本恢复的保证。本轮没有联网抓取、核实真实撤回，也没有将合成候选应用到运行时。

## 5. 独立预期与后续研究

本轮新增断言包括未知/零对照、非口服否定用例、不同单位/basis/实体隔离、区间开闭端点、失效手工覆盖、异常 JSON 边界、候选状态改变与 gate disposition、账户切换后旧回执不可见。测试均使用固定合成输入，不携带患者数据。

当前有界验证：Chrome 的事实可比性、capsule、候选回执、诊断 panel 与口服/未知蛋白共 32 个用例通过；最终 shared selector/生产餐食/严格浏览器 archive 的 17 个用例复测通过（与前者有重叠）。Node 的独立 replay 传输/规范化 6 个用例通过。最终 Dart VM 的 selector、实际餐食路径、目录/CDSS、SQLite 与浏览器 archive、可执行契约和来源修订共 75 个用例通过；独立回执租约和精确标签来源展示的 13 个维护用例通过。可执行契约的路径预期明确增加了口服 route，排序与原缺失字段集不变；未通过放宽身份门禁处理预期漂移。统一 source/config/schema pins 与全库验收仍由主实施流程完成，不能把这些有界验证写成完整闭包通过。

最后一次口服 score scope 修复的实际餐食正/负例与既有数据库餐食、route 门禁共 19 个 Dart VM 用例通过；明确口服保留四项既有 modifier，其他路线删除这些 modifier 并保留复核判定。相关最终源码静态检查无问题。

下一项有界敏感性实验应固定：明确口服即时释放产品、同源同 basis 的食物组成、给药时间/剂量及配置 identity；分别扰动份量、蛋白缺失、来源状态、餐食时间。独立预期是：同源份量投影按克数比例变化；缺失或不支持来源进入 withheld；来源过期/撤回阻断相应研究 provider；不能据“风险分数变小”推断患者更安全。记录输入、来源修订、as-of、配置 digest、数值/解释变化与失败原因后，再决定是否提出参数研究。尚未开展患者校准或缓释产品定量模型升级。
